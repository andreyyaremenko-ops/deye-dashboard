# Спайк: читання Deye через Solarman-стік

Мета: перевірити на реальному залізі, що стік віддає дані локально, і зібрати
сирі дампи регістрів для тестів парсера V5 (етап 3 плану).

## Запуск

Ноутбук має бути в тій же WiFi-мережі, що й стік. Залежностей нема, тільки Python 3.10+.

```bash
python3 solarman_spike.py --discover-only        # 1. чи бачимо стік взагалі
python3 solarman_spike.py                         # 2. пошук + читання регістрів
python3 solarman_spike.py -v                      # те саме з hex усіх кадрів
python3 solarman_spike.py --scan 192.168.1.0/24   # якщо broadcast не відповідає
python3 solarman_spike.py --host 192.168.1.50 --serial 2712345678
```

Серійник логера (10 цифр, починається зазвичай на 17/21/27/41) є на наліпці
стіка та в його web-UI: `http://<ip>` (admin/admin).

## Що збирає

`dumps/<serial>_<час>.json`: сирі hex кожного запиту й відповіді V5, плюс
таблиця регістрів (dec/hex). Ці файли і є тестовими фікстурами для парсера.

## На що звернути увагу

- Стік тримає одного TCP-клієнта на 8899. Закрити Home Assistant / Solar
  Assistant на час тесту.
- Якщо на порт 8899 не підключається, а web-UI працює: прошивка стіка може
  обмежувати локальний доступ. Це критична інформація для проєкту.
- Якщо весь діапазон 0-120 повертає `illegal data address`, спробувати `--slave 0`
  або інші діапазони через `--ranges`.
- Тип пристрою в reg 0 підкаже, яку карту регістрів шукати далі
  (2 string, 3 однофазний гібрид, 5/6 трифазний гібрид).
